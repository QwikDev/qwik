# AWS Adapter

Qwik Router AWS Adapter allows you to connect Qwik Router to [AWS Lambda](https://docs.aws.amazon.com/lambda/latest/dg/nodejs-handler.html?icmpid=docs_lambda_hel).

## Installation

To integrate the `aws-lambda` adapter, use the `add` command:

<PackageManagerTabs>
<span q:slot="pnpm">
```shell
pnpm run qwik add aws-lambda
```
</span>
<span q:slot="npm">
```shell
npm run qwik add aws-lambda
```
</span>
<span q:slot="yarn">
```shell
yarn run qwik add aws-lambda
```
</span>
<span q:slot="bun">
```shell
bun run qwik add aws-lambda
```
</span>
</PackageManagerTabs>

The adapter will add a new `vite.config.ts` within the `adapters/` directory, and a new entry file will be created, such as:

```shell
└── adapters/
    └── aws-lambda
        └── vite.config.ts
└── cloudformation/
    └── template.yaml
└── src/
    └── entry_aws-lambda.tsx
└── Makefile
```

Additionally, within the `package.json`, the `build.server` and `deploy` scripts will be updated.

## Deploy to AWS

The adapter deploys behind a single [CloudFront](https://aws.amazon.com/cloudfront/) distribution: static assets served from an S3 origin, server-side rendering from a [Lambda Function URL](https://docs.aws.amazon.com/lambda/latest/dg/urls-configuration.html) origin. There's no API Gateway and no third-party deploy framework — the stack is plain CloudFormation ([`cloudformation/template.yaml`](https://github.com/QwikDev/qwik/blob/main/starters/adapters/aws-lambda/cloudformation/template.yaml)), deployed with the AWS CLI via the included `Makefile`.

You'll need AWS credentials with permission to create the resources above, either as environment variables or a profile in `~/.aws/credentials`.

First, create (or reuse) an S3 bucket to hold the packaged CloudFormation template:

```shell
export DEPLOYMENT_BUCKET="qwik-deployment-bucket"
make setup-deployment
```

Then build and deploy — this builds the app, packages and deploys the CloudFormation stack, and syncs the static build output to S3:

```shell
export DEPLOYMENT_BUCKET="qwik-deployment-bucket"
export STACK_NAME="qwik-stack"
make deploy
```

CloudFormation names the static bucket for you — S3 bucket names are global, so a fixed
default would clash across users — and prints the site's CloudFront URL once the stack is up.

Done!

<Note>The SSR Lambda needs the request's real host to compute its [CSRF-protection origin](/docs/deployments/node/index.mdx). Since the Function URL origin would otherwise only see CloudFront's own domain, a CloudFront Function copies the viewer's `Host` header into `x-forwarded-host` on the way in, and the `HOST_HEADER` environment variable tells the SSR handler to read it from there. This works unchanged if you later put a custom domain in front of CloudFront.</Note>
