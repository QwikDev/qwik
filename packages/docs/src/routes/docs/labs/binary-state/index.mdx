# Binary state

**Stage:** `alpha`

<Note>
  Binary state is experimental. The format may still change, and it is not readable by older
  versions of Qwik.
</Note>

Qwik serializes the state of your application into the HTML so the client can resume. By default
that state is JSON. With `binaryState`, it is a compact stream that the client reads directly,
without `JSON.parse` and without building intermediate arrays.

On pages with a lot of state this makes the container ready sooner and the first interaction
faster, and the document is smaller before compression. On small pages the difference is not
noticeable. The core bundle grows by about 1.4 kB (brotli).

To use it, add `experimental: ['binaryState']` to your `qwikVite` plugin options:

```ts
// vite.config.ts
import { defineConfig } from 'vite';
import { qwikVite } from '@qwik.dev/core/optimizer';

export default defineConfig(() => {
  return {
    plugins: [
      qwikVite({
        experimental: ['binaryState'],
      }),
    ],
  };
});
```

No application code needs to change. The flag also switches the payloads of `routeLoader$`,
`routeAction$` and `server$` to the same format.

## What to check before you enable it

- **Serve UTF-8.** The state must be decoded as UTF-8. Qwik Router sends
  `Content-Type: text/html; charset=utf-8`; if you serve HTML yourself, make sure the charset is
  set.
- **Do not edit the state text.** Anything that rewrites text inside the
  `<script type="qwik/state">` elements or inside a loader or action response, such as a proxy or
  a middleware doing search and replace, breaks the state. Change the data before it is serialized
  instead.
- **Deploy server and client together.** A client built with the flag only reads binary state, so
  the HTML and the JavaScript must come from the same build.
